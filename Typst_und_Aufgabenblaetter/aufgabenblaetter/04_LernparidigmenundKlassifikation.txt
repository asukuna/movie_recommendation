Supervised Learning: Lernen mit Beispielen
Definition: Algorithmen lernen durch gelabelte Trainingsdaten, Muster zu erkennen und 
vorherzusagen.
Kernelemente:
Eingabedaten (X): Features der zu analysierenden Objekte
Ausgabedaten (Y): Korrekte Antworten/Labels für jedes Beispiel
Trainingsdaten: Sammlung von Input-Output-Paaren (X, Y)
Modell: Mathematische Funktion zur Abbildung von X auf Y
Verlustfunktion: Misst Fehler zwischen Vorhersage und tatsächlichem Wert
Hauptaufgabentypen:
Klassifikation: Zuordnung zu diskreten Kategorien (z.B. Spam-Erkennung)
Regression: Vorhersage kontinuierlicher Werte (z.B. Hauspreise)
Prozess:
Sammlung gelabelter Daten für Training und Test
Training durch Minimierung der Verlustfunktion
Validierung auf separaten Testdaten
Anwendung auf neue, ungesehene Daten
Algorithmen:
Lineare Regression, Logistische Regression, Entscheidungsbäume, Neuronale Netze

Unsupervised Learning: Entdecken ohne Vorgaben
Definition: Algorithmen finden selbstständig Muster und Strukturen in ungelabelten Daten.
Kernelemente:
Eingabedaten (X): Features ohne zugehörige Labels
Keine Ausgabedaten (Y): Keine vordefinierten korrekten Antworten
Ähnlichkeitsmaße: Bestimmen Beziehungen zwischen Datenpunkten
Modell: Entdeckt Strukturen oder Gruppierungen in Daten
Zielfunktion: Optimiert interne Datenrepräsentation statt Vorhersagegenauigkeit
Hauptaufgabentypen:
Clustering: Gruppierung ähnlicher Datenpunkte (z.B. Kundensegmentierung)
Dimensionsreduktion: Komprimierung von Daten (z.B. PCA)
Prozess:
Sammlung ungelabelter Daten
Anwendung von Algorithmen zur Mustererkennung
Interpretation der gefundenen Strukturen
Validierung durch Domänenexperten oder indirekte Metriken
Algorithmen:
K-Means, DBSCAN, Hierarchisches Clustering, Autoencoders, t-SNE

Semi-Supervised Learning: Das Beste aus beiden Welten
Definition: Kombination weniger gelabelter mit vielen ungelabelten Daten für effizientes Lernen.
Kernelemente:
Kleine Menge gelabelter Daten (X, Y)
Große Menge ungelabelter Daten (nur X)
Annahmen: Ähnliche Daten haben ähnliche Labels
Modell: Nutzt beide Datentypen für bessere Generalisierung
Pseudo-Labeling: Generiert Labels für ungelabelte Daten
Hauptaufgabentypen:
Verbesserte Klassifikation mit begrenzten Labels
Domänenadaption bei unterschiedlichen Datenverteilungen
Prozess:
Training mit gelabelten Daten
Erweiterung durch ungelabelte Daten mittels spezieller Techniken
Iterative Verbesserung des Modells
Evaluation auf separatem Testset
Algorithmen:
Self-Training, Co-Training, Graph-basierte Methoden, FixMatch, MixMatch

Reinforcement Learning: Lernen durch Interaktion
Definition: Agent lernt optimale Aktionen durch Interaktion mit einer Umgebung.
Kernelemente:
Agent: Entscheidungsträger, der Aktionen ausführt
Umgebung: Reagiert auf Aktionen mit neuen Zuständen
Belohnungen: Feedback-Signal für ausgeführte Aktionen
Policy: Strategie des Agenten zur Aktionsauswahl
Wertfunktion: Schätzt zukünftige Belohnungen für Zustände/Aktionen
Hauptaufgabentypen:
Sequentielle Entscheidungsfindung (z.B. Robotersteuerung)
Optimierung von Strategien (z.B. Spielen)
Prozess:
Agent beobachtet aktuellen Zustand
Agent wählt und führt Aktion aus
Umgebung liefert Belohnung und neuen Zustand
Agent aktualisiert seine Strategie
Algorithmen:
Q-Learning, Deep Q-Networks, Policy Gradient, PPO, A3C
ML Klassifikation:Klassifizierung und Regression sind technisch unterschiedliche Aufgabentypen für ML:
Klassifizierung: Datenpunkte zwischen zwei oder mehr Gruppen unterscheiden
Regression: Datenpunkten einen variablen Wert einer kontinuierlichen Skala zuweisen
Warum zusammenfassen?
Bei einer Klassifizierung werden (meistens) Wahrscheinlichkeitswerte ermittelt um darauf basierend 
die Zuweisung des Datenpunkts zu einer Gruppe durchzuführen. Klassifizierung kann deshalb von 
einer übergeordneten Betrachtung als Regression auf Wahrscheinlichkeitswerte betrachtet werden.

(insbesondere Klassifikation, Clustering, NLP) orchestriert werden, um Datenbestände intelligent zu organisieren und 
zugänglich zu machen
Bisherige Modelle waren auf die Erzeugung von einem Output bezogen auf einen erwarteten Input konditioniert. 
Datenkataloge konzentrieren sich auf das Herausarbeiten von relevanten Items. Sie erzeugen ein Ergebnisset bezogen 
auf einen gegebenen Input (eingegebener String, hochgeladenes Bild, gesprochener Satz, ...), oder erzeugen diesen 
proaktiv (Playlist Vorschläge, empfohlene Filme, ...).

Generative Ansätze im ML fokussieren sich auf die Erzeugung von Daten basierend auf dem 
gegebenen Input. Sie sind nicht gedacht für das Kategorisieren, Bewerten, die Extraktion von 
Informationen oder die Organisation von Daten.
Die Ausgaben von für diesen Ansatz verwendete Modelle haben in der Regel eine große Bandbreite  
und Ergebnisse können für den gleichen Input variieren. Die Ausgaben sind generell weniger 
eingeschränkt als bei anderen Ansätzen. Das macht deren EInsatz in produktiven Anwendungen 
riskanter. Oft werden generative Ansätze zum trainieren oder für Anwendungen eingesetzt, die 
gegenüber den Modellausgaben toleranter sind (Übersetzung, Bilderzeugung, Chatbot, ...).
zudem ist der Einsatz von generativen Ansätzen in der Regel sehr leistungsintesiv, was sich direkt auf 
die Skalierbarkeit und auch die Wirtschaftlichkeit der geplanten Anwendung auswirkt.
